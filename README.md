# Litmus 石蕊

> 把"我觉得"变成"数据说"。

一个本地运行的开源工具：用自然语言选股，并且回看一个条件在历史上出现之后，股票到底怎么走。

---

## 这个项目解决什么问题

散户每天都在接触各种"选股方法"：

- "放量突破年线是买入信号"
- "MACD 金叉要涨"
- "财报后有惯性，超预期的会继续涨"

常见的行情软件都能告诉你**今天哪些股票符合这些条件**。

但很少有工具回答那个真正重要的问题：**符合了又怎样？**

第一版先回答其中一半：**这只股票历史上每次出现这个信号之后，接下来 1 周、1 个月、3 个月怎么走，同期市场平均又怎么走。**
全市场层面的有效性检验（"这个信号在 5000 只股票上统计显著吗"）在 P1。

---

## 第一版能做什么

三种回答。

### ① 股票表：今天哪些股票满足条件

```
你问：昨天哪个股票成交量比前一周平均高 40% 以上？

代码       名称      行业    收盘价   涨跌幅   成交额    放大倍数
600xxx    某某某    电子     12.30   +4.2%   8.4亿     1.83
...                                          共 37 只
```

支持筛选、排序、取前 N 名，三者可以任意组合。"今年以来涨幅最大的前 50 名"也是这一类。

### ② 板块表：哪个板块最近热

```
你问：最近一周哪个板块的成交额最大？

板块        成交额(5日)   涨跌幅(5日)  成交额较前20日   涨停家数
光模块        1240亿        +8.4%        1.7 倍          6
...                                                    共 10 个
```

板块有两种口径：申万行业（31 个一级行业）和概念板块（如光模块、AI）。概念板块用通达信口径，需要 Tushare 6000 积分，没有权限时系统会明确告知。

两种口径能看的历史长度不同：申万行业从 2012 年起，概念板块从 2025 年 3 月起。可用区间会显示在确认卡上。

### ③ 个股回看：这只股票历史上每次出现这个信号之后怎么走

```
你问：茅台每次放量突破年线之后表现如何？

贵州茅台 · 放量突破年线 · 2016 年以来 23 次
日期          之后1周   之后1月   之后3月   同期市场(1月)   备注
2019-01-30    +4.4%    +12.9%    +26.3%      +8.0%
2020-05-22    -0.8%     +3.1%    +15.7%      +2.2%       买入顺延1天(涨停)
...
平均          +1.2%     +3.1%     +8.4%      +1.1%
这只股票平时任意一天之后 1 个月的平均涨跌：+1.9%
扣除 0.3% 交易成本后，之后 1 个月平均：+2.8%
⚠ 仅 23 次，样本偏少，不能排除是运气
```

"之后 1 个月涨跌"的算法：从信号出现的**次日开盘价**算到**第 20 个交易日的收盘价**。用次日开盘价是因为信号收盘后才能确认，用当天收盘价等于用了当时还不知道的信息。表格里的涨跌都不扣交易成本，成本单独列在下面一行，方便看清原始涨跌和成本各占多少。

"同期市场"默认是当日股票池的等权平均（和触发的股票同一个池、同一套算法），也可以在确认卡上改成沪深300。持有期从买入日起算：如果次日开盘涨停买不进，会顺延到能买进的那天，再往后数 20 个交易日。

## 第一版不做什么

这些都在 Roadmap 的 P1，不是永远不做：

- 全市场有效性判定（"这个信号在全市场统计显著吗"）与显著性检验
- 防过拟合机制：样本外锁定、调参次数计数与警告
- 用户自定义事件（个股回看只支持下面的事件库）
- 概念板块的历史成分（第一版只有当前成分）
- 龙虎榜、游资、人气榜、机构目标价、涨停原因
- 资金门槛与容量估算

## 交互：两步出结果

```
1. 用自然语言提问
        ↓
2. 系统返回【确认卡】——把模糊的描述翻译成明确的定义
        ┌──────────────────────────────────────┐
        │ 我把你的描述理解成：                    │
        │                                      │
        │ 日期      2026-09-11（最近已收盘交易日）│
        │ 条件      成交额 > 前20日均值 × 2 倍    │
        │           （2 倍是默认值，可修改）       │
        │ 范围      沪深A股，剔除 ST/停牌/次新    │
        │ 排序      放大倍数从高到低，取前 50 只   │
        │                                      │
        │ ⚠ 「成交量」已理解为成交额（元）         │
        │                                      │
        │        [确认并运行]   [修改]           │
        └──────────────────────────────────────┘
        ↓ 用户确认
3. 确定性执行 → 结果
```

**确认卡是整个产品的关键设计**：它同时解决了消除歧义、教育用户、建立可复现契约三件事。确认卡的内容一旦确定，跑一万次结果完全相同。

有些提问模糊到猜不出默认值（比如"最近哪个板块最强"里的"最近"），系统会先问清楚再往下走，不会替你猜。

答不了的问题（比如"现在能买茅台吗"）系统不会硬答，而是给出几个能回答的相关问题让你选。

## 预置事件库

个股回看支持这 15 个事件，参数可调（均线天数、放量倍数、连板数等）：

| 类别 | 事件 |
|---|---|
| 均线 | 突破均线（默认年线）、跌破均线、均线金叉、MACD 金叉 |
| 量能 | 单日放量、放量突破均线、缩量回调 |
| 价格 | 创 N 日新高（默认 250 日）、创 N 日新低 |
| 涨跌停 | 涨停、连板（N 连板）、跌停 |
| 日历 | 财报披露日、业绩预告日、除权除息日 |

股票表和板块表不受这个清单限制，任意条件都可以筛选。

**为什么个股回看有清单限制**：回看要回答"每次发生之后怎样"，前提是这个条件确实"在某一天发生"。像"市值低于 200 亿"这种会连续成立几百天的条件，没有"发生的那一天"，第一版不做回看。

**事件只在"由不满足变为满足"的那一天记一次**：连续 5 天创新高只算 1 次，三连板只在第 2 天算 1 次，不会把同一段行情重复计入。

## 数据

- 数据源：**Tushare Pro，需要 5000 积分及以上**。概念板块另需 6000 积分，没有权限时相关功能自动关闭并提示。
- 范围：2016 年至今，沪深 A 股（含已退市股票，不含北交所）。
- **仓库不附带任何行情数据**，首次使用时在页面上点「同步历史数据」下载到本地。
- 所有数据留在你自己的机器上。

## 快速开始

```bash
git clone https://github.com/<you>/litmus-quant.git
cd litmus-quant

cp .env.example .env
# 填入 LLM_BASE_URL / LLM_API_KEY（火山引擎 Anthropic 兼容端点）
# 填入 TUSHARE_TOKEN（Tushare Pro，积分需 5000 及以上）

docker compose up
# 打开 http://localhost:8080
```

首次打开页面后点击「同步历史数据」，系统会从今天倒着往 2016 年下载沪深 A 股数据。**覆盖到最近两年（约 15 分钟）就可以开始提问**，更早的历史在后台继续补，页面上会标明已经补到哪一年；提问用到的历史超出已覆盖区间时，确认卡会直接告诉你。全部补完约一个多小时（取决于数据接口的速度），只需要做一次，之后每次同步只补最新几天。

## Roadmap

| 阶段 | 内容 | 状态 |
|---|---|---|
| **P0** | 数据层 + 表达式引擎 + 三种回答（股票表 / 板块表 / 个股回看）+ 确认卡 | 🚧 开发中 |
| **P1** | 全市场有效性判定 + 显著性检验 + 防过拟合（样本外锁定、调参计数）+ 自定义事件 + 龙虎榜等数据 | 计划中 |
| **P2** | 因子评价（IC/ICIR/分层）+ 多因子组合 + 组合调仓单 | 计划中 |
| **P3** | 纸面组合跟踪 + 信号推送 + 策略失效告警 | 计划中 |
| **P4** | **量化研究 Agent** | 构想中 |

### 关于 P1 的有效性判定

第一版的个股回看只能给出单只股票的历史，样本往往只有二三十次，很难分辨是规律还是运气。P1 会把同一个信号放到全市场跑一遍，给出触发次数、相对同期市场的超额收益、以及统计显著性。

这件事必须配套做防过拟合：用户每调一次参数就多一次"碰巧找到好看数字"的机会，所以要锁定最近一年数据不让调参时看到，并记录调参次数。检验和防过拟合是一起的，所以放在同一个阶段。

### 关于 P4 的量化 Agent

后续会引入一个自动化的研究循环：

```
提出假设 → 生成因子表达式 → 回测 → 诊断失败原因 → 提出新假设 → ...
```

目标不是"自动生成赚钱策略"，而是把研究员从实现劳动中解放出来 ——
一个想法从"提出"到"验证"，人工需要 2-3 小时，这个循环压缩到 5-15 分钟。

**但这个功能有一条硬性前置条件**：必须先有足够严格的裁判（基准对照、样本外锁定、
迭代计数、多重检验折减）。LLM 生成假设的成本接近零，意味着它能以人类无法企及的速度
产生假阳性。没有严格的检验机制，这个循环就是一台工业级过拟合机器。

所以 P4 排在最后，不是因为技术难，而是因为它必须建立在 P0-P2 的基础上。

## 明确不做的事

| 不做 | 原因 |
|---|---|
| 给个股打分（0-100） | 不可证伪的数字就是负债 |
| 给目标价、说"建议买入" | 同上，且有合规风险 |
| 实盘下单 | 避开券商接口、资金安全、合规三重麻烦 |
| 高频/日内策略 | 数据要求和竞争环境都不适合散户 |
| 内置爬取券商研报 | 版权风险。研报请用户自行上传 |
| 让 LLM 直接产出买卖信号或自由问答 | LLM 有前视污染（训练数据含未来信息）、不可复现、无法评估统计显著性。系统里 LLM 只负责翻译提问和审查修改，所有数字都由确定性代码算出 |
